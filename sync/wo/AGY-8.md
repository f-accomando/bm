## AGY-8a - estrarre e strutturare (bm-light, 60 min)
- Leggere scaffold-workflow-EN.pdf per intero (pymupdf: testo di tutte le 28 pagine) e docs/WORKFLOW.md. Il prompt copre TUTTE le sezioni della guida: nessuna sezione omessa. Elencare in fondo al messaggio di consegna la corrispondenza sezione della guida -> sezione del prompt.
- Il prompt e' scritto per Claude (seconda persona imperativa, in inglese: e' la lingua dei file del repo), con regole positive ("fai cosi'"), come nelle Writing rules di CLAUDE.md. Struttura fissa:
  1. Scopo e come usare il file (una frase: leggi tutto, poi esegui i passi in ordine).
  2. Domande iniziali all'utente (massimo 6, tutte insieme in un solo messaggio): nome del progetto, descrizione, linguaggio e stack, branch principale, comando di build, comando dei test. Con le risposte si sostituiscono i segnaposto <PROJECT>, <main-branch>, <build-cmd>, <test-cmd> e simili.
  2b. Controllo di un progetto esistente (PRIMA di scrivere qualsiasi file): Claude esegue `git status` e un elenco dei percorsi della tabella 3 che esistono gia' (CLAUDE.md, AGENTS.md, GEMINI.md, .claude/**, .github/workflows/**, .gitignore, docs/**, scripts/**, tools/**, SYNC.md e simili). Se la cartella ha modifiche non salvate, chiede all'utente di fare commit o stash prima. Se nessun percorso esiste, procede come progetto nuovo.
  2c. Percorsi gia' esistenti: regola fissa, nessun file esistente viene sovrascritto, cancellato o spostato senza risposta esplicita dell'utente. Per ogni percorso in conflitto Claude legge il file esistente, mostra all'utente in 3 righe cosa contiene e propone UNA tra: (a) tenere il file dell'utente e aggiungere solo le sezioni mancanti del template in coda o in una sezione dedicata (unione), (b) tenere il file dell'utente e salvare quello del template accanto come `<nome>.scaffold` per un confronto successivo, (c) sostituire, solo dopo aver salvato una copia in `.scaffold-backup/<data>/<percorso>` e dopo una conferma scritta dell'utente. Il default e' (b) per i file di istruzioni (CLAUDE.md, AGENTS.md, GEMINI.md) e per .github/workflows/ci.yml, (a) per .gitignore. Le domande per tutti i conflitti vanno in un solo messaggio, con la proposta consigliata per ciascuno, e Claude aspetta le risposte prima di procedere. Per CLAUDE.md/AGENTS.md esistenti Claude propone l'unione per sezioni: mantiene tutte le regole dell'utente, aggiunge le sezioni del workflow che non contraddicono quelle esistenti e segnala all'utente ogni contraddizione senza risolverla da solo. Stessa regola per le cartelle docs/ e scripts/ con nomi uguali (un file alla volta, mai la cartella intera) e per gli hook o le impostazioni gia' presenti in .claude/ (settings.json, agenti e skill con lo stesso nome: tenere quelli dell'utente).
  2d. Alla fine Claude scrive un elenco di cio' che ha creato, unito, lasciato accanto come `.scaffold` o salvato in `.scaffold-backup`, e dice come annullare (`git status`, `git checkout -- <file>`), cosi' nulla e' irreversibile. Nessun commit automatico: lo decide l'utente.
  3. Albero dei file da creare: tabella percorso -> scopo -> chi lo scrive, con TUTTI i file dell'albero del template che servono a un progetto (CLAUDE.md, AGENTS.md, GEMINI.md, .claude/agents/*.md, .claude/skills/{docs-loop,docs-map,work-order}/SKILL.md, SYNC.md, sync/_template.md, sync/operators.toml, sync/inbox/README.md, docs/{WORKFLOW,ROADMAP,open-decisions,progress}.md, docs/progress/{core,sync}.md, docs/spec/*, docs/agents/ledger.txt, scripts/{agent_audit,ci_audit,consistency,docs_audit,selftest}.py, tools/sync_{check,hdr,watch}.py, .github/workflows/ci.yml, .ci-audit.toml, .gitignore). Esclusi: video/, examples/, .claude/skills/explainer-video/, i PDF.
  4. Da dove prendere i file: DECISIONE FISSA, il repo f-accomando/scaffold e' pubblico, quindi i file NON sono incorporati nel prompt: il prompt dice a Claude di scaricarli. In cima al file due variabili: `SCAFFOLD_REPO=https://github.com/f-accomando/scaffold` e `SCAFFOLD_REF=claude/workflow-template` (con la nota: quando la PR 1 sara' fusa, sostituire con `main`). Passi: `git clone --depth 1 --branch $SCAFFOLD_REF $SCAFFOLD_REPO <cartella temporanea>` (alternativa senza git: curl del file da `https://raw.githubusercontent.com/f-accomando/scaffold/$SCAFFOLD_REF/<percorso>`), poi copiare nel progetto SOLO i file della tabella 3, nei percorsi indicati, senza copiare la cartella .git. Per ogni file la tabella dice: percorso, scopo, e che cosa cambiare dopo la copia (segnaposto da sostituire con le risposte, righe da cancellare perche' non servono, es. le righe del template per linguaggi non usati). Per i file con segnaposto elencare i segnaposto esatti trovati con grep nel repo reale (grep -n '<[A-Za-z-]*>' sul file). Gli script Python (scripts/*.py, tools/*.py) si copiano senza modifiche; indicare scopo, uso da riga di comando ed exit code.
  5. Verifica finale che Claude esegue: python scripts/selftest.py, python scripts/docs_audit.py score, python scripts/consistency.py check (se presenti gli script) o l'elenco dei file creati.
  6. Prima sessione: cosa dire all'utente alla fine (3 comandi di uso quotidiano).
- Copiare i testi dei file dall'albero reale a HEAD del branch, non riscriverli a memoria.
