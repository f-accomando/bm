## Change (no open design choices)
1. `src/bm/r3d.h`: after `r3d_point`'s declaration (`:268`): 
```
/* M44 step 2: a pool of 3D particles in structure-of-arrays form (7 float arrays of `cap` entries: x y z vx vy vz
 * life; cap a multiple of 16, at most 4096), stepped by the ARM or by the backend (the QPUs) with the same result
 * bit for bit. One step: vy = vy - g; x = x + vx; y = y + vy; z = z + vz; life = life - 1.0f (single precision, one
 * operation per statement, entries with life <= 0 stepped too). */
#define R3D_PFX_MAX 4096
typedef struct { int cap, next; float *a; uint32_t *rgb; } r3d_pfx_t;
r3d_pfx_t *r3d_pfx_new(int cap);                 /* NULL if cap < 1 or > R3D_PFX_MAX or no memory; cap rounded up to 16 */
void r3d_pfx_free(r3d_pfx_t *p);
int r3d_pfx_add(r3d_pfx_t *p, v3_t pos, v3_t vel, float life, uint32_t rgb);   /* the next slot, round robin; its index */
void r3d_pfx_step(r3d_t *r, r3d_pfx_t *p, float gravity);   /* the backend's pfx_step if it has one and takes it, else the ARM */
uint32_t r3d_pfx_draw(r3d_t *r, const r3d_pfx_t *p, float radius);   /* r3d_point for each entry with life > 0; the pixels */
int r3d_pfx_live(const r3d_pfx_t *p);            /* entries with life > 0 */
```
and in `r3d_backend_t`, after `shadow`: `int (*pfx_step)(void *ctx, float *a, int cap, float g);   /* M44, optional: the pool stepped by the backend (the QPUs); 1 if it took it */`.
2. `src/bm/r3d.c`, after `r3d_point`: the implementation: `r3d_pfx_new` allocates `a` with `aligned_alloc(64, 7 * cap * 4)` (zeroed) and `rgb` with `calloc`; `r3d_pfx_add` writes the slot `next` (`next = (next + 1) % cap` after), sets the 7 floats and the colour, returns the slot; `r3d_pfx_step`: `if (r->backend && r->backend->pfx_step && r->backend->pfx_step(r->backend->ctx, p->a, p->cap, gravity)) return;` else the loop over ALL `cap` entries of the five statements above; `r3d_pfx_draw` loops over entries with `life > 0` and sums `r3d_point(r, (v3_t){ x, y, z }, radius, rgb, 0)`; `r3d_pfx_live` counts.
3. `tests/bm/test_bm.c`: `test_pfx()` called from `main` after `test_3d()`: (a) `r3d_pfx_new(100)` gives `cap == 112`; `r3d_pfx_new(5000) == NULL`; (b) add 3 particles, step twice with `g = 0.5f` and compare every float with the closed form written in the test (`vy = vy0 - 1.0f` after two steps, `x = x0 + 2 * vx0`, `y = y0 + (vy0 - 0.5f) + (vy0 - 1.0f)`, `life = life0 - 2`); (c) with `life = 1.5f`, after two steps `r3d_pfx_live() == 0` and `r3d_pfx_draw` returns 0; (d) a backend whose `pfx_step` returns 1 and counts its calls: `r3d_pfx_step` calls it once and does not touch the pool; one that returns 0: the ARM loop runs; (e) a particle in front of a camera set as `test_3d` sets one draws more than 0 pixels with `r3d_pfx_draw`.
