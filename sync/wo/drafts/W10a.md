Objective: `qpu_pfx_step` advances every particle of a structure-of-arrays pool by one step, bit for bit as the ARM formula below, and `make test-gpu3d` proves it on 4096 particles launched on 4 QPUs.

## The step (the contract shared with W10b/W10c)
Pool: 7 float arrays of `cap` entries one after the other (`a[0..cap)` x, then `y`, `z`, `vx`, `vy`, `vz`, `life`); `cap` a multiple of 16. One step for entry i, in this order, single-precision IEEE, no fused multiply-add: `vy = vy - g; x = x + vx; y = y + vy; z = z + vz; life = life - 1.0f`. Dead entries (`life <= 0`) are stepped like the others (no branch per particle).

## Change (no open design choices)
1. `SHADERS["qpu_pfx_step"]` in `tools/qpuasm.py`, comment `# M44 step 2: one step of the particle pool (see W10a). Uniforms: 0 = bus address of a (the 7 arrays), 1 = cap, 2 = first block, 3 = number of blocks (16 particles each), 4 = g (float bits).` Per block `b` (loop with the W08 branch, three delay slots filled with the loop's own bookkeeping): for each of the 7 arrays load 16 floats with a TMU read at `a + 4 * (k * cap + 16 * b + element number)`, compute with `fsub`/`fadd` (the ALU `fadd`/`fsub`, never `fmul`+`fadd` fused: there is no fused op on the QPU), write the 7 results to the VPM (7 rows) and store them with ONE 7-row DMA store of block mode with a memory stride of `4 * cap` bytes (the Reference Guide's "VPM DMA Store Block Mode Setup"); wait for the store (`vw_wait`) before the next block.
