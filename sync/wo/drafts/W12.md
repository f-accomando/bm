## Change (no open design choices)
1. `src/rgb30/mali.h`, before `#endif`:
```
/* M41 phase 2: a frame of up to MALI_MAX_DRAWS draws, each n triangles of ONE colour (xyz = 3 floats a vertex, in
 * pixels of the surface, z in 0..1, 3n vertices; rgb 0xRRGGBB), at most MALI_BATCH_MAX triangles in all. The surface is
 * w x h XRGB8888 (w, h multiples of 16, at most 1920 x 1080) at target (CPU pointer) / target_pa (what the GPU sees,
 * 64-aligned) with `pitch` bytes a row; it is first cleared to `clear` (0xRRGGBB): what was there is not kept. Draws are
 * drawn in the order given (no depth test). After a good mali_probe with the same hw. 0 drawn, 1 the jobs ended but the
 * first draw's first triangle centre is still `clear`, -1 failed or refused. */
#define MALI_MAX_DRAWS  64
#define MALI_BATCH_MAX  1024
typedef struct { const float (*xyz)[3]; uint32_t n, rgb; } mali_draw_t;
int mali_frame(const mali_hw_t *hw, uint8_t *target, uint64_t target_pa, uint32_t pitch, uint32_t w, uint32_t h,
               uint32_t clear, const mali_draw_t *draws, uint32_t ndraws);
/* places in hw->mem the test reads */
#define MALI_FRAME_VERTS      0x10000   /* all vertices, 4 floats each (x y z 1), draw after draw */
#define MALI_FRAME_POSITIONS  0x20000   /* what the vertex jobs write, same order */
#define MALI_FRAME_PUSH       0x30000   /* per draw 64 bytes: the pushed words, colour at +16 */
```
2. `src/rgb30/mali.c`: `static int frame_build(...)` = the body of `triangle()` before the `run_on` calls, with: vertices of draw d copied (as `(x, y, z, 1)`) at `MALI_FRAME_VERTS + 16 * first_vertex(d)`; the per-draw jobs and descriptors at `MEM_DRAWS` (`#define MEM_DRAWS 0x40000`) `+ 0x400 * d` (0x400 bytes a draw, after the vertex arrays; the shared pieces stay where `triangle()` has them: heap descriptor, tiler context, the shader code at `MEM_VS`/`MEM_FS`, the vertex Renderer State `MEM_VRSD`, local storage, viewport); each draw has: a vertex job and a tiler job, its own fragment Renderer State + Blend (at `+ 0x100`), its push block (`MALI_FRAME_PUSH + 64 * d`, colour floats at +16) and its uniform buffer descriptor; the attribute buffer of draw d points at its slice of `MALI_FRAME_VERTS` (`48 * n` bytes, 16 per vertex) and the position varying buffer at its slice of `MALI_FRAME_POSITIONS`; `md_vertex_job(job, 3 * n, &vd)`, `.index_count = 3 * n`; job indices `2d + 1` (vertex, dep 0 for d = 0 else the previous tiler job `2d`) and `2d + 2` (tiler, dep `2d + 1`), `next` pointers chaining all jobs; `md_tiler_context(..., w, h, HIERARCHY_MASK, ...)`; `md_viewport(..., 0, 0, w, h, 0, 0, w - 1, h - 1)`; the heap (`HEAP_SIZE`) as now; then `fbd(..., w, h, target_pa, pitch, clear)` and `job_fragment(..., w, h, ...)`. ## Open decisions (for SPV before assigning)
1. The surface is cleared before the draws (the Frame Buffer Descriptor in `fbd()` clears, it does not load): W13 uses a key colour for "not covered" and copies the covered pixels into the page, so 2D already on the page survives. A tile LOAD of the existing content would be a new WO.
2. No depth test (no Z buffer in `fbd`): W13 sorts back to front per frame; correct for convex flat-coloured scenes only.
3. One shared vertex Renderer State, one fragment Renderer State per draw: if H1/H6 show the GPU rejects a Blend shared across draws, nothing here changes (each draw already has its own).
