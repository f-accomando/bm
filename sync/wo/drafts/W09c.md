Objective: `v3d_qpu_run()` (declared in W09b) writes the user-launch registers of the V3D, waits for the completion count with a timeout, and `v3d_init()` gives the VPM to the user programs (a share) without breaking the vertex pipeline; the kernel compiles.

## What exists today (found with git grep on the base)
- `v3d_init()` at `src/gpu/v3d.c:86-123` writes `wr(V3D_VPMBASE, 0)` at `:112` ("all of the VPM to the vertex pipeline (as Linux: no user programs)") and resets CT0/CT1; `V3D_VPMBASE` is `0x504` (`:35`); register access is `rd()`/`wr()` (`:57`, `:62`) and `dmb()` after groups of accesses; the mailbox enable is `PROP_ENABLE_QPU` (`:48`).
- `wait_count(reg, cs_reg, timeout_us, us)` polls a count register and an error bit with a timeout and records the wait for the audio accounting (`:156-182`); `wait_add` (`:150`).
- Registers named in `docs/progress/v3d.md` (M44 step 1, "Toolkit"): `SRQPC / SRQUA / SRQUL / SRQCS` at `0x430, 0x434, 0x438, 0x43C`: write the uniform address, then the length, then the program counter (the last queues the QPU); completion count in bits 23:16 of `SRQCS`; needs `VPMBASE > 0`; reset by the mailbox `0x30012`.

## Change (no open design choices)
1. Defines next to `V3D_VPMBASE` (`src/gpu/v3d.c:35`): `V3D_SRQPC 0x430`, `V3D_SRQUA 0x434`, `V3D_SRQUL 0x438`, `V3D_SRQCS 0x43C`, `SRQCS_ERROR (1u << 7)`, `SRQCS_DONE_SHIFT 16` (mask 0xFF). Check each against the VideoCore IV Architecture Reference Guide's QPU scheduler register table before use; a mismatch is `BLOCKED` with the table line.
2. `v3d_init()` (`:112`) keeps `wr(V3D_VPMBASE, 0)` (the vertex pipeline keeps all of the VPM for every 3D job: no change for the games). `v3d_qpu_run` (step 4) sets the share itself: `wr(V3D_VPMBASE, QPU_VPM_ROWS_USER)` before the launch and `wr(V3D_VPMBASE, 0)` after the wait (also on failure), with `#define QPU_VPM_ROWS_USER 4` (units as the reference defines `VPMBASE`: state the unit and the resulting number of rows in the report; the user program needs 1 row; `BLOCKED` if the reference gives no unit).
3. A file-static `int qpu_user_ok` (0 at boot), `int v3d_qpu_ok(void) { return qpu_user_ok; }` and `void v3d_qpu_set_ok(int ok) { qpu_user_ok = ok; }` (both declared in `src/gpu/v3d.h` by W09b; W09d's probe, which lives in `gpu3d.c`, calls the setter). `v3d_qpu_run` itself does not check `qpu_user_ok` (the probe has to call it before the flag is set).
4. `int v3d_qpu_run(uint32_t code, uint32_t unif, uint32_t nunif, int count, uint32_t timeout_us)`: refuse (`return -1`) if `!ready`, `count < 1 || count > 12`, or a 3D job is in flight (`v3d_busy()` at `:34` of the start block); `wr(V3D_SRQCS, SRQCS_ERROR | (1u << 8) | (1u << 16))` (clear the error and both counts); for i in 0..count-1: `wr(V3D_SRQUA, unif + 4 * nunif * i); wr(V3D_SRQUL, nunif); wr(V3D_SRQPC, code);`; `dmb()`; then `wait_count(V3D_SRQCS, V3D_SRQCS, timeout_us, NULL)` is NOT usable (its count is bits 7:0): write a second static `wait_srq(count, timeout_us)` that polls `(rd(V3D_SRQCS) >> SRQCS_DONE_SHIFT & 0xFF) == count`, fails on `SRQCS_ERROR` or on `timer_ticks() - t0 > timeout_us`, adds the wait to `v3d_wait_us` the way `wait_add` does (`:150`), calls `snapshot()` (`:77`) on failure, and returns 0 or -1. On failure also `wr(V3D_SRQCS, SRQCS_ERROR | 1u << 8 | 1u << 16)`.
5. Caches, as `v3d_run` does (`src/gpu/v3d.c:206-216` `cache_all`, used at `:246` before a job and after it at the end of `v3d_run`): in `v3d_qpu_run` call `cache_all(&dummy)` (`uint32_t dummy = 0;`) before the first register write (the uniforms and the code are in ARM memory) and again after the wait, so the ARM reads what the QPUs stored.
6. Do not change any existing function's behavior otherwise.

## Open decisions (for SPV before assigning)
1. The share is taken only while a user program runs (no 3D job is in flight then: `v3d_qpu_run` refuses otherwise), so the games' vertex pipeline never sees a smaller VPM. If the hardware shows the hardware does not allow changing `VPMBASE` while idle, H7 finds it.
2. The "queue" of the plan is the QPU scheduler's own queue (the SRQ registers queue up to 4 programs); a software dispatch queue is not in this WO.
