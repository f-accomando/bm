## What exists today (found with git grep on the base)

The GPU memory is `hw->mem` (4 MiB, uncached), heap at `0x100000` (1 MiB, `src/rgb30/mali.c` `MEM_HEAP`), the jobs below `0x80000`.
- `g16_t` has `px` (RGB565), `w`, `h`, `stride` (pixels).

2. `src/rgb30/mali.c`, a section at the end: a static buffer `tris[MALI_BATCH_MAX]` of `{ float v[3][3]; float key; uint32_t rgb; }`; `static void cb_tri(...)`: ignore (return) if `kind != R3D_KIND_COLOUR || depth != R3D_DEPTH_WRITE` (W13b makes r3d send nothing else; this is the guard); colour = mean of the three corners' `a`, `b`, `c` times 255, rounded, as `0xRRGGBB`, with `0xFF00FF` (the key) changed to `0xFF01FF`; sort key = mean of the corners' `z` (1/depth: larger is nearer); vertices `(x, y, 0.5)`; if the buffer is full, `mali_backend_flush(g)` first (g from the callback's argument, cast away const as `gpu3d.c` does for its flush; say how you did it). `static void cb_zclear(void *ctx, const g16_t *g)`: `mali_backend_drop()`. The backend struct: `.tri = cb_tri, .zclear = cb_zclear, .guard = 0, .tex_screen = 0`, `.colour_only = 1` and `.ctx = NULL`.
   `mali_backend_flush(g16_t *g)`: nothing waiting -> 0; surface = `hw->mem + 0x200000`, `pa = hw->mem_pa + 0x200000`, `sw = (g->w + 15) & ~15`, `sh = (g->h + 15) & ~15`, `pitch = (sw * 4 + 63) & ~63`; refuse (-1, the buffer dropped) if `sw > 1920 || sh > 1080 || 0x200000 + pitch * sh > hw->mem_size`; sort the buffered triangles ascending by key (far first; a stable insertion sort on indices is enough: the buffer is at most 1024); group consecutive equal `rgb` into draws (a new draw also at 64: when the 65th draw would start, draw what is grouped so far with `mali_frame`, resolve, and go on with a fresh frame); call `mali_frame(hw, surface, pa, pitch, sw, sh, 0xFF00FF, draws, nd)` (its return 0 or 1 both count as done; -1 -> `mali_backend_drop()` and return -1); resolve: for y < g->h, x < g->w: `p = *(uint32_t *)(surface + y * pitch + 4 * x) & 0xFFFFFF`; if `p != 0xFF00FF` then `g->px[y * g->stride + x] = (p >> 19 & 31) << 11 | (p >> 10 & 63) << 5 | (p >> 3 & 31)`; clear the buffer; return 0. (XRGB little-endian as `mali_frame` leaves it: `0x00RRGGBB`.)

## Open decisions (for SPV before assigning)
1. Flat shading: the corners' colours are averaged (the shader has one colour per draw); Gouraud and textures stay on the ARM. A frame of the Stages 3D map (textured floor) therefore goes to the ARM at once (W13b): the Mali backend helps scenes of flat meshes only until a textured shader exists.
2. Painter's sort by mean 1/depth is exact for convex objects drawn in one frame, not for intersecting ones; phase 4 or a Z buffer fixes it. The key colour `0xFF00FF` means "not covered".
3. The 2 MiB offset of the surface and 2 MiB of room (720x720x4 = 2 MiB fits exactly) are fixed here; `mem_size` is 4 MiB on the RK3566 (`src/rgb30/gputest_rgb30.c:77`).
