## APP-5b-1 — mkwords legge api.tsv; predict espone le voci (bm-coder, 40 min)
Passo 0: `src/ai/api.tsv` ha prima riga `# generated by scripts/mkapi.py ...` e righe `name\tsignature\tarea\ttext`; `scripts/api_lint_allow.txt` esiste. Se il formato è diverso: BLOCKED.
`scripts/mkwords.py`:
- `tsv_api()`: legge `src/ai/api.tsv`, salta le righe `#`, divide su `\t` in 4 campi; dict ordinato `name → (signature, area, text)`.
- `api_text(s)`, in quest'ordine: (1) `\[([^\]]+)\]\([^)]+\)` → `\1`; (2) `<br>`, `<br/>`, `<br />` → spazio; (3) toglie `**` e `` ` ``; (4) spazi multipli a uno, strip; (5) sostituzioni: — e – → `-`, → → `->`, ← → `<-`, × → `x`, ≤ → `<=`, ≥ → `>=`, … → `...`, ’ e ‘ → `'`, “ e ” → `"`, · → `.`, U+00A0 → spazio; (6) ogni altro carattere oltre 127 non in `CP437` → `?`; (7) se la lunghezza supera 480: taglia all'ultimo spazio entro la posizione 477 e aggiunge `...` (D3). Si applica a signature e text.
- `allow_names()`: per ogni riga di `scripts/api_lint_allow.txt`: strip; salta vuote o `#`; il nome è `line.split('#')[0].strip()`.
- In `main()`, `api = kb_api()` diventa `api = tsv_api()`. Nel ramo `lang == 'lua'`: `uni.setdefault(name, 0)` e `funcs.add(name)` solo per nomi senza `:`; la sezione `api` diventa una riga `name\tsig\tarea\ttext\n` per nome (ordinati), con `api_text` già applicato; nuova sezione `allow = long_string(...)`, un nome per riga.
- `kb_api()` resta, usata solo da `--stats`, che stampa anche `api: N names; kb names missing from api.tsv: M <nomi>` (D2). Aggiornare la docstring (riga `api`, nuova riga `allow`).
`Makefile` riga 124: aggiungere `src/ai/api.tsv scripts/api_lint_allow.txt` a `WORDS_SRC`.
`src/ai/predict.lua`, `loader()`: parse dell'api con `([^\t\n]+)\t([^\t\n]*)\t([^\t\n]*)\t([^\n]*)\n` → `d.api[name] = { sig =, area =, text = }`, con `coroutine.yield()` ogni 128 righe come nel ciclo di `big`. `if src.allow` → `d.allow[name] = true` per riga; aggiungere `allow = {}` al costruttore di `d`. Nuove funzioni pubbliche prima di `return P`: `P.api(name)` → `dict("lua").api[name]` o nil; `P.wrap(text, width)` → array di righe (a capo sugli spazi; una parola più lunga di `width` si spezza a `width`; nessuna riga vuota finale).

Nuovi check: `P.api("cls").sig == "cls([c])"`; `P.api("cls").text` inizia con `fills the screen`; `P.api("cls").area == "draw"`; `P.api("nonexistent_xyz") == nil`; `P.wrap("aa bb cc", 5)` = `{"aa bb","cc"}`; `P.wrap("abcdefgh", 3)` = `{"abc","def","gh"}`.

## APP-5b-2 — lint in Lua uguale a api_lint.py (bm-coder, 45 min)
`src/ai/predict.lua`, nuove funzioni:
- `P.strip_code(text)`: toglie commenti (`--` fino a fine riga, `--[[ ]]` con `=` livellati) e stringhe (`".."` e `'..'` con escape, `[[..]]` con livelli). Il contenuto diventa spazi e gli a-capo restano (i numeri di riga non cambiano).
- `P.defined(lines)`: set dei nomi definiti, con le stesse regole di `scripts/api_lint.py`: `function N`, `local function N`, `local N[, M] =`, `N = function`, parametri di `function x(a, b)`, variabili di `for N[, M] in`; comprende nomi locali e globali dei metodi: riprodurre esattamente lo script.
- `P.lint(lines, o)`: testo = `table.concat(lines, "\n")` passato a `strip_code`; chiamate = ogni `([%a_][%w_]*)%s*%(` il cui carattere precedente non corrisponde a `[%w_.:]` (come la lookbehind di `api_lint.py`); nomi noti = nomi di `dict("lua").api` senza `.` né `:` ∪ primo segmento dei nomi con `.` o `:` ∪ `LUA_STD` (alla lettera da AGY-2a: `assert error ipairs pairs next pcall xpcall select tonumber tostring type unpack rawget rawset rawequal rawlen setmetatable getmetatable require collectgarbage print string table math coroutine utf8`) ∪ parole chiave (`function if while until return and or not elseif in local`) ∪ `dict("lua").allow` ∪ `P.defined(lines)` ∪ `o.defined` (set facoltativo); restituisce `{ line = N, name = S }` nello stesso ordine e con gli stessi duplicati di `api_lint.py` (leggerlo prima di scrivere).
