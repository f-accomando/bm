## BETA-7a - `scripts/doc_refs.py`, controllo di percorsi, comandi e collegamenti (bm-coder, 40 min)
- CLI: `python scripts/doc_refs.py FILE... [--root DIR] [--final] [--max-lines N]`; `--root` di default la radice del repo. Uscita `FILE:RIGA: <motivo>` per errore; exit 0 nessun errore, 1 almeno uno, 2 per uso/I-O.
- Elementi letti: (i) span inline tra backtick fuori dai blocchi; (ii) ogni riga dei blocchi ``` e `::: copy` ... `:::`. Ogni elemento si divide su spazi in token; si salta un token con `<` o `>`; dalla fine si tolgono `,` `.` `;` `:` `)` e un suffisso `:N` o `:N-M`.
- R1 percorsi del repo: un token (tolto un `./` iniziale) che inizia con `docs/`, `scripts/`, `src/`, `carts/`, `tests/`, `tools/`, `manuals/`, `sdk/`, oppure uguale a `easy_install.sh`, `Makefile` o `rgb30.mk`. Con `*`: `glob` sotto `--root` con almeno un risultato. Finale `/`: directory esistente. Altrimenti file esistente. Se manca: `missing path <p>`.
- R2 percorsi della console: un token che inizia con `/` deve iniziare con `/carts/` o `/bm/`, altrimenti `unknown console path <p>`. Percorsi senza `/` iniziale (`bm/`, `bm/config.txt`) non si controllano.
- R3 comandi. `make`: il primo token successivo senza `=` e che non inizia con `-` e' il target. Se non contiene `/`, deve esistere una riga `^<target>\s*:` (regex con `re.escape`) in `Makefile` o `rgb30.mk`, oppure comparire in una riga `.PHONY:`; altrimenti `unknown make target <t>`. Un target con `/` stampa `note: make target not checked <t>` su stdout (non errore). `./easy_install.sh <sub>`: un `<sub>` che non inizia con `-` deve corrispondere a `^\s*<sub>\)` in `easy_install.sh`, altrimenti `unknown easy_install.sh command <sub>`.
- R4 link markdown `[t](x)` non immagine: si saltano `http://`, `https://`, `#...`; si toglie `#anchor`; il file va risolto relativo alla cartella del documento, altrimenti `broken link <x>`. Le immagini non si controllano.
- R5: con `--final`, ogni `[TO FILL:` o `[DA COMPLETARE:` da' `gap left`. R6: con `--max-lines N`, un file con piu' di N righe da' `too long: <n> lines (max N)`.
- Passo 0 (le regole non sono state provate sui file reali): lanciarlo su `manuals/content/en/install-sd.md` e `manuals/content/en/editor-sdk.md` e riportare l'uscita. Un errore vero di quei manuali NON si corregge (fuori perimetro): si elenca. Un falso positivo dovuto a una regola: BLOCKED con le righe.
- Test `tests/tools/test_doc_refs.py` (unittest, subprocess, come `tests/tools/test_agent_audit.py`) con radice temporanea (`Makefile` con `image:`, `easy_install.sh` con `    send) x ;;`, `docs/a.md`). Casi: file valido → 0; `docs/nope.md` → 1 con la riga giusta; link rotto → 1; `make nosuch` → 1; `make TARGET=rgb30 image` → 0; `./easy_install.sh nosuch` → 1; `/foo/x` → 1; `/carts/MYGAME.BME` → 0; `<NAME>` saltato; segnaposto con `--final` → 1, senza → 0; `--max-lines 2` su 3 righe → 1.
- Verifica: `python tests/tools/test_doc_refs.py` → OK.
