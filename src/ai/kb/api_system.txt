# Structure of a cartridge, time, system, saves, files.

== callbacks
kind: api
name: _update
title: _init, _update, _draw - la struttura di un gioco
title_en: _init, _update, _draw - the structure of a game
ask: come è fatto un gioco | struttura di una cartuccia | game loop | ciclo del gioco
ask: dove metto la logica | dove disegno | funzioni principali | main loop
ask: quante volte al secondo | 60 fps | skeleton of a game | scheletro del gioco
see: game_skeleton
text:
_init() una volta all'avvio; poi 60 volte al secondo _update() (la logica:
input, movimento, collisioni) e _draw() (il disegno). Lua fa la logica, il
disegno è in C. Budget: 16,7 ms per fotogramma in tutto.
text_en:
_init() once at the start; then 60 times a second _update() (the logic:
input, movement, collisions) and _draw() (the drawing). Lua does the logic,
the drawing is in C. Budget: 16.7 ms per frame in all.
code:
function _init()
  x, y = 320, 180
end

function _update()
  if btn(1) then x = x + 2 end
end

function _draw()
  cls(0)
  circfill(x, y, 8, 0xFFD050)
end

0 KiB usati da Lua, 1 ms dell'ultimo fotogramma, 2 fps, 3 numero del

== frameskip
kind: api
name: frameskip
title: frameskip(n) - il tempo del gioco anche quando il disegno è lento
title_en: frameskip(n) - the game's time even when drawing is slow
ask: il gioco rallenta quando gli fps scendono | il gioco va al rallentatore | frame skip
ask: saltare fotogrammi | update più volte del draw | game slows down when fps drop
ask: tempo del gioco costante | fixed timestep
see: stat, guide.devkit, perf_tips
text:
Un gioco che avanza di 1/60 s a ogni _update rallenta quando un fotogramma
costa più di 16,7 ms. frameskip(n): prima di ogni _draw girano fino a n
_update, quanti ne servono per il tempo passato (i fotogrammi in mezzo non
si disegnano). 1 è il default (uno per fotogramma). btnp() conta un tasto
una volta sola; stat(15) dice quanti _update sono girati.
text_en:
A game that moves on 1/60 s at every _update slows down when a frame
costs more than 16.7 ms. frameskip(n): before each _draw up to n
_update run, as many as the time passed needs (the frames in between are
not drawn). 1 is the default (one per frame). btnp() counts a button only
once; stat(15) says how many _update ran.
code:
function _init()
  frameskip(4)   -- fino a 4 _update per ogni _draw
end

== devkit
kind: api
name: devkit
title: devkit(modo) e devinfo(...) - l'overlay delle prestazioni dal gioco
title_en: devkit(mode) and devinfo(...) - the performance overlay from the game
ask: accendere il dev kit dal gioco | overlay delle prestazioni con il pad | show the performance overlay
ask: righe mie nel dev kit | aggiungere informazioni al dev kit | devinfo
see: guide.devkit, stat, frameskip
text:
devkit() dà il modo dell'overlay: 0 spento, 1 semplice, 2 dettagliato
(ogni fase del fotogramma, la GPU, i triangoli), 3 funzioni (le dieci che
costano di più); devkit(modo) lo cambia, per esempio con Select sul pad
(F11 è della tastiera). devinfo(riga, ...) mette fino a 4 righe del gioco
nella pagina dettagliata.
text_en:
devkit() gives the overlay's mode: 0 off, 1 simple, 2 detailed
(every phase of the frame, the GPU, the triangles), 3 functions (the ten
that cost the most); devkit(mode) changes it, for example with Select on
the pad (F11 is the keyboard's). devinfo(line, ...) puts up to 4 lines of
the game on the detailed page.
code:
local enemies = {}
if btnp(9) then devkit((devkit() + 1) % 4) end   -- Select
if devkit() == 2 then devinfo("nemici " .. #enemies) end

== profile
kind: api
name: profile
title: profile() - le funzioni che costano di più
title_en: profile() - the functions that cost the most
ask: quale funzione è lenta | dove va il tempo del fotogramma | profiler
ask: le funzioni più pesanti del gioco | cosa rallenta il gioco | profiling per funzione
ask: which function is slow | where does the frame time go | function profiler
see: devkit, guide.devkit, stat
text:
Il profiler delle funzioni: F11 tre volte (la pagina delle funzioni del
dev kit) o profile(true) dal gioco. profile() dà le funzioni dell'ultimo
secondo, la più cara per prima: name, where ("main.lua:120" o "[C]"),
self (ms per fotogramma, il suo tempo), total (con quelle che chiama),
calls (solo per le funzioni in C). profile(false) lo spegne.
text_en:
The profiler of functions: F11 three times (the functions page of the
dev kit) or profile(true) from the game. profile() gives the functions of
the last second, the costliest first: name, where ("main.lua:120" or
"[C]"), self (ms per frame, its own time), total (with the ones it
calls), calls (only for the functions in C). profile(false) turns it off.
code:
function _init() profile(true) end
function _draw()
  for i, f in ipairs(profile()) do
    if i > 5 then break end
    print(f.name .. " " .. f.self, 4, i * 8, 7)
  end
end

== breakpoint
kind: api
name: breakpoint
title: breakpoint() e F8 - il debugger di bm Code
title_en: breakpoint() and F8 - the debugger of bm Code
ask: debugger | fermare il gioco su una riga | punto di interruzione | breakpoint
ask: vedere le variabili mentre il gioco gira | eseguire passo passo | step by step
ask: stop the game on a line | inspect variables | debug step by step
see: log, cart_run
text:
In bm Code F8 mette un punto di interruzione sulla riga e F5 prova il
gioco: si ferma lì e mostra il codice, le variabili e la pila. F10 la riga
dopo, F8 dentro una chiamata, Shift+F8 fuori dalla funzione, F5 continua,
Esc ferma il gioco e torna sulla riga (pad: A, X, Y, Start, Select).
breakpoint("perché") nel codice ferma il gioco provato da bm Code o
dall'SDK; negli altri casi non fa niente.
text_en:
In bm Code F8 puts a breakpoint on the line and F5 tries the game: it
stops there and shows the code, the variables and the stack. F10 the next
line, F8 into a call, Shift+F8 out of the function, F5 goes on, Esc stops
the game and goes back to the line (pad: A, X, Y, Start, Select).
breakpoint("why") in the code stops the game tried from bm Code or from
the SDK; in the other cases it does nothing.
code:
if hp < 0 then breakpoint("vita sotto zero") end

== cart_build
kind: api
name: cart_build
title: cart_build(progetto) - fa il gioco .bm di un progetto .bme
title_en: cart_build(project) - builds the .bm game of a .bme project
ask: fare il gioco dal progetto | build del gioco | costruire il .bm | build the game
ask: differenza tra bm e bme | progetto bme | file bme | what is a .bme file

text: Un .bm è un gioco: gli strumenti di bm lo leggono e ne prendono codice e

text_en: A .bm is a game: bm's tools read it and take its code and assets, but

cart_write also return the file written. cart_build makes the project's game
in /carts (Ctrl+B in the SDK, Build the game in the menu): the next time it

local ok, file = cart_save(path, { lua = code })

== udp
kind: api
name: udp_send
title: udp_open / udp_send / udp_recv - pacchetti UDP per giocare in rete
title_en: udp_open / udp_send / udp_recv - UDP packets for network play
ask: pacchetti udp | socket udp | mandare dati grezzi a un'altra console
ask: udp | send a raw packet on the network | udp socket | broadcast sulla lan
keys: udp, pacchetto, socket
see: bmnet, nnet
text: s = udp_open(porta) apre un socket (nil senza rete, o se il giocatore non
lo permette: la prima volta la console glielo chiede); udp_send(s, ind,
porta, dati) manda una stringa (al massimo 1024 byte, "*" = tutta la LAN);
udp_recv(s) dà il prossimo pacchetto e chi l'ha mandato, o nil. net_ip()
l'indirizzo della console. Overbit gioca in lockstep: viaggiano solo i

text_en: s = udp_open(port) opens a socket (nil without a network, or if the
player does not allow it: the first time the console asks them);
udp_send(s, address, port, data) sends a string (at most 1024 bytes,
"*" = the whole LAN); udp_recv(s) gives the next packet and who sent it,
or nil. net_ip() the console's address. Overbit plays in lockstep: only
the players' commands travel.
code:
local s = udp_open(47310)
if s then udp_send(s, "*", 47310, "ciao") end
local d, ip = s and udp_recv(s)
