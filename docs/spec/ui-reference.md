# Per-device UI Reference: Keys, Menus, and Screen

This document is the fixed reference for device-specific input controls, menu behaviors, default screen resolutions, and scaling rules across supported bare-metal targets.

| Monitor | The text console after the menu (Ctrl+Shift+Esc, or Settings > System). It opens the bm shell: a frame that fills the screen. Inside the frame is the file list of the SD card: the folder (`SD:/` at start), then its entries as a tree, folders first, each with a folder icon or a floppy icon. The items are icons in the middle of the bottom border: bm menu gui (the cartridge menu), Command line (the `bm:` prompt, selected at start), Shell Code, Shell SDK (a 6502 chip icon: the IDE with five tabs Project, Code, Sprite, Map, Sounds on F1 to F5; Project has the platform tiles NES, SNES, bm, the cartridge menu, the PCB picture and the memory facts (the arrows move and change; the SDK, its lists and the ROM side move with the arrows only: letters do not move); Code is a text editor (the keys of bm Code: Shift selects, Ctrl+arrows skip words, Ctrl+C, X, V copy, cut, paste, Ctrl+D duplicates a line, Ctrl+Z undoes, Ctrl+Y redoes, PgUp and PgDn move a page), and with a ROM open (Esc menu, Open ROM: the ROMs of `/nes` and `/snes`) it splits in two, the editor left and the ROM right (header and hex dump), and Ctrl+T or Ctrl+Tab moves the focus; Ctrl+W closes the ROM; with the focus on the ROM, `a` changes between the hex dump and a read-only ASM listing (a NES ROM of mapper 0 or 3 shows its whole PRG; with another mapper the listing is one PRG bank, the last one first, and `+` and `-` change the bank; the address of an 8 KB bank that is not the last is a guess from its calls, marked `guess`; SNES from the reset vector to the end of its bank); `t` changes between the dump and the bytes drawn as 8x8 tiles in greys (a NES ROM starts at its CHR ROM; `b` reads a SNES ROM as 4, 2 or 8 bpp; the arrows move a cursor of one tile (Shift selects a rectangle, Ctrl+A all that shows, Ctrl+C copies the tiles), `,` and `.` move the view one byte, Ctrl+Left and Ctrl+Right one tile; the hex dump and the ASM listing have the cursor and the move keys of the editor (Shift selects, Ctrl+A selects all, Ctrl+C copies the selection or the line into the clipboard of the editor, Ctrl+V in the editor pastes it; they cannot be changed); `+` and `-` set the tiles in a row (1 to 32, 16 when a ROM opens) and `o` changes between the 8x8 and the 8x16 order, where a tile and the next are above each other); the Sprite tab has on its left a canvas of 16 x 32 tiles and on its right the tiles of the same open ROM (one ROM and one view of its tiles for both tabs; Open ROM from the Sprite tab stays there); Ctrl+T moves between the two; on the canvas the arrows move the cursor, Shift selects, Ctrl+C copies, Ctrl+X cuts, Ctrl+V pastes the copied tiles at the cursor and Del empties the cells; `i` imports the sprite sheet of the ROM into the canvas, in the order of the ROM (a CHR ROM of at most 512 tiles whole; else 512 tiles from the first tile that the view shows), and asks for a second `i` when the canvas has tiles; in a NES or SNES project the canvas is code: each change writes its tiles into the `;@sprites` section of the source (a block from `;@tiles` to `;@tiles-end`: a `.chr` block for NES, bytes after `sprites_chr:` for SNES), and the canvas is read from that block when the code changes or a project opens (Ctrl+Z in the Code tab undoes a change of the canvas; a block that cannot be read shows its line in red and the canvas does not change it); the canvas of a bm project is in no file, so the SDK asks before it closes with tiles on it; Ctrl+E hides the ROM side of the tab (Code or Sprite, each on its own) and shows it again, with the ROM still open; the answer to a key of the ROM side shows on the last row of the ROM pane; Esc opens the menu New, Open, Open ROM, Save, Save as, Build ROM, Build and run, Exit; Ctrl+B builds, Ctrl+R builds and runs the ROM in bm NES or bm SNES; New starts a NES or SNES project from a program that builds as it is and shows a blue screen (the platform can change until the project has a name or code, then it is fixed); a NES or SNES project is a `.bmr` in `/bmr` with its source code, a bm project a `.bme` in `/bme`; Build ROM writes `/nes/NAME.nes` or `/snes/NAME.sfc`), System (Info, Log, bm3D, 3D Bench, Reboot), Network (WiFi, Pair controller, Send reports), Help. Under the border, one line tells what the selection does. In the bar: a, d or Left, Right move; Enter opens a group (its box opens above its icon: w, s or Up, Down move, Enter runs, a or Esc close) or runs an item; w or Up goes to the last row of the list; Esc opens the cartridge menu. In the list: w, s or Up, Down move; s on the last row goes back to the bar; Enter opens a folder (`..` goes up), plays a `.bm` or `.b16`, starts bm NES on a `.nes` and bm SNES on a `.sfc` or `.smc`, opens a text file in Shell Code; any other file gets one line; a or Left goes to the folder above; Esc goes back to the bar. `:` takes one line of commands everywhere. System > Info is a box with the main facts, where a typed word runs a command (`exit`, Esc or Ctrl-D leave). The prompt has a history of 16 lines (Up, Down), Tab completion of commands, subcommands and `set` keys, and line editing (Left, Right, Home, End, Backspace, Del, Ctrl-U, Ctrl-C). It works on the serial line, on a USB keyboard and on the network console. `:` and a line runs that line once (the PC tools use it). The help (`h`) is made from the command table | `core/src/kernel/monitor.c` (`commands`), `core/src/kernel/monitor_cmd.c`, `core/src/kernel/shell_sdk.c`, `tests/qemu_test.py:test_monitor_prompt`, `tests/qemu_test.py:test_shell_sdk_skeleton`, `tests/qemu_test.py:test_shell_sdk_code_split`, `tests/qemu_test.py:test_shell_sdk_editor_keys`, `tests/qemu_test.py:test_shell_sdk_build`, `tests/qemu_test.py:test_shell_sdk_template`, `tests/qemu_test.py:test_shell_sdk_run` | implemented |

## Open decisions

- **Role of button A on RGB30**: B is OK and Y is cancel/back. Button A has no role in the menus (PAD-Y-1: Y is the only back button). A is OK only with `confirm=a`.
- **Role of button Y in menus on Raspberry Pi**: Button Y has no defined role in menus or system tools on Raspberry Pi; in games it maps by position (`docs/spec/divergences.toml:365`).
