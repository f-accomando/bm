# API: the SNES machine

Part of the game API. Index and basics: [API.md](../API.md). The machine is in C (`src/bm/snes_*.c`, entry
points in `src/bm/api_snes.c`); the cartridge `carts/snes` is its user interface. See
[progress/snes.md](../progress/snes.md).

| Function | Description |
|---|---|
| `snes_load(bytes)` | loads a ROM (`.sfc` or `.smc`, a copier header is skipped) and resets the machine: `true`, or `nil` and the reason |
| `snes_dsp_firmware(bytes, [data])` | the firmware of the DSP chip of the loaded ROM (`snes_info().dsp` is 1 to 4): one file of 8192 bytes (`dspN.rom`), or the program (6144 bytes) and the data (2048 bytes) as two strings. Call it after `snes_load`; the machine resets. `true`, or `nil` and the reason (the game then runs without the chip). See [progress/snes-dsp.md](../progress/snes-dsp.md) |
| `snes_reset()` | a reset of the machine |
| `snes_frame(pad1, pad2, [render])` | runs one frame of the machine with two pads (`render` false: the picture is not drawn, for a frame that is skipped); a pad is bits: `0x8000` B, `0x4000` Y, `0x2000` Select, `0x1000` Start, `0x0800` up, `0x0400` down, `0x0200` left, `0x0100` right, `0x0080` A, `0x0040` X, `0x0020` L, `0x0010` R |
| `snes_to_sheet([x, y])` | copies the picture into the cartridge's sprite sheet at `(x, y)` (multiples of 8; the sheet must hold 256 x 224 pixels there), opaque, and returns the lines: `sspr(x, y, 256, lines, dx, dy, false, false, 3)` then draws it three times bigger, by the GPU where the GPU draws the 2D |
| `snes_tiles(addr, bpp, tiles, cols, [sx, sy, cgbase, pal])` | draws tiles of the video RAM into the cartridge's sprite sheet at `(sx, sy)`: `addr` is the byte address of the first tile, `bpp` 2, 4 or 8 (8, 32 or 64 bytes a tile), `tiles` up to 4096, `cols` tiles in a row (up to 64). The colours are the colour RAM entries `cgbase + pal * 2^bpp + pixel` (`pal` is ignored with 8 bpp; `cgbase` 128 for sprites); colour 0 is transparent. Returns the width and the height in pixels. Then `sheet_png` and `doc_write` make a PNG in `/docs` that bm Pixel imports |
| `snes_draw(target, [w, h])` | copies the picture (256 pixels wide, 224 or 239 lines) to the top left of a render target; with `w` and `h` it scales it to that size (nearest pixel, much faster than `target_blit` with a scale); returns the number of lines |
| `snes_info()` | `{title, mapping, size, sram, dsp, dsp_fw}` of the loaded ROM (`mapping` is `"LoROM"` or `"HiROM"`; `dsp` is the DSP chip 1 to 4 of the cartridge, 0 for none; `dsp_fw` is true when its firmware is loaded) |
| `snes_sram([bytes])` | without an argument: the battery RAM as a string if it changed since the last call, else `nil`; with `bytes`: puts them in the battery RAM |
| `snes_debug([addr])` | what a stuck game waits for: `{pc, wai, stp, io, spc, spc_pc, inidisp, tm, nmi, frames, oam, regs}` (`io` the last six I/O registers read; `oam` the 544 bytes of the sprite table as a string; `regs` a text line with the sprite priority rotation, the BG mode, the layers on and the scroll registers; with `addr`, also `vram` (32 bytes of the video RAM at `addr`), `cgram` (the 32 colours bytes of sprite palette 3) and `vmap` (256 characters, one for each 256 bytes of video RAM: `.` zero, `F` all FF, `x` other); `spc` is `"boot"`, `"run"` or `"halt"`) |
| `snes_peek(addr24, [len])` | a byte of the S-CPU address space, or with `len` a string of `len` bytes (up to 65536). It has no side effect: a read of `$2138`-`$213B`, `$2180`, `$4016`, `$4017`, `$4210`, `$4211` returns the byte that the next read returns and does not step the latch or clear the flag. The sound ports and the cart chip registers read as 0. It costs no clock |
| `snes_poke(addr24, byte)` | writes a byte as the CPU does (a register write has its effect; a write to the ROM does nothing). It costs no clock |
| `snes_regs()` | `{a, x, y, s, d, db, pb, pc, p, e, pc24, cycle, frames, wai, stp}`: the registers of the S-CPU (`e` is the emulation flag, `pc24` is `pb << 16 \| pc`, `cycle` counts master clocks since the start of the machine) |
| `snes_step()` | runs one instruction (a pending interrupt is taken first); returns the new `pc24`. The line and the frame do not advance: the clock counts on, and the next frame ends the line. Use it between frames or after `snes_run` stopped |
| `snes_break(addr24)` | arms a breakpoint on the instruction at `addr24` (up to 8); `snes_break(nil)` clears all. Returns the count, or `nil` and a text when 8 are armed |
| `snes_run([pad1, pad2, render])` | like `snes_frame`, but it stops before an instruction that has a breakpoint. Returns `nil` when the frame is done, or the `pc24` where it stopped; call it again to go on with the same frame (the instruction at the breakpoint runs first). With no breakpoint armed it runs the normal loop. `snes_frame` never stops on a breakpoint |
