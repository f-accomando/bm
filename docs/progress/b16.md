# The `.b16` Profile 

This document tracks the architecture, sandbox rules and progress of the **`.b16`** format and runtime profile for the **bm** console.

Spec reference: [`docs/B16.md`](../B16.md) §0.

---

## 1. Project Goal and Philosophy

The `.b16` profile defines a resource-constrained environment (inspired by the PICO-8 philosophy but with 16-bit power), guaranteeing **perfectly identical and reproducible behavior on Raspberry Pi Zero W and PowKiddy RGB30**:
- **Same cartridge container**: dedicated profile flag in the `BMCART` header (`BM_FLAG_B16 = 2`).
- **Fixed resolution**: square **360×360** (or native 720×720 on RGB30).
- **Color palette**: 256 indexed colors (`SHEET8`).
- **Memory budget** (as built; the runtime is the same as a `.bm`, see `docs/B16.md`):
  - Lua heap: **64 MB** (`LUA_MEM_LIMIT`, `src/script/luavm.c:13`). The 4 MB of the first plan was never built.
  - Graphics: the `SHEET8` sheet of the cartridge. No graphics banks (D6).
  - Persistent save: **32 KB** per slot (`SAVE_MAX`, `src/bm/rt_internal.h:48`).
  - Maximum cartridge file size: no limit of its own. The Market takes 100 MB a file.
  - No arbitrary token limit.
- **Audio**: 8 polyphonic voices.
- **CPU**: target 60 fps; no CPU budget and no automatic throttle promised (D4).
- **Controls**: SNES-style layout (d-pad + A, B, X, Y, L1, R1, Start, Select).
- **No sandbox** (D1): a `.b16` is a target. It has the same API as a `.bm`, including `ls`, `cart_*` and `math.random`.

| Step | Description | Status |

Key facts, checked in the code on 25 Oct 2026:

- The Pi boxes a square header in a 16:9 page: `bm_video_enter` (`src/bm/runtime.c`) puts 360x360 in 640x360, 140 pixels of black on each side.
- The RGB30 shows any header as big as fits, with the same shape: `fb_init_game` calls `fb_init_mode` with `FB_FILL` (`src/rgb30/fb.c`). A 640x360 header gives 720x405. On the real display `window()` (`src/rgb30/rk_display.c`) centres the image on the 720x720 panel (read in the code, not verified on hardware). The QEMU virt display (`plat_virt.c`) has no scaler and shows the image 1:1.
- `screen(w, h)` on a square panel knows the modes of `square_modes` (`src/bm/runtime.c`).
- `safe_area()` and `aspect()` are added by W3.
- Header bytes 120..127 and flag bit 4 hold the compatibility block (`src/bm/bm.h`, `src/bm/format.c`). A `.b16` without the block reads as Pi plus RGB30 through its extension.
- No `bm.info` has a `targets:` line and no Makefile rule passes `--targets` (W5 to W7 change this).
- `SAVE_MAX` is 32 KB (`src/bm/rt_internal.h:48`). `LUA_MEM_LIMIT` is 64 MB (`src/script/luavm.c:13`).

## Rules (do not break)

- Every cartridge writer keeps header bytes 120..127 and flag bit 4 (the compatibility block). `project.c` clears only bytes 104..119 (`bm_set_built_from`).
- An old file (bit 4 clear) reads as Pi only. An old `.b16` reads as Pi and RGB30.
