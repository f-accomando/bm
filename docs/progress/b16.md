# The `.b16` Profile 

This document tracks the architecture, sandbox rules and progress of the **`.b16`** format and runtime profile for the **bm** console.

Spec reference: [`docs/B16.md`](../B16.md) §0.

---

## 1. Project Goal and Philosophy

The `.b16` profile defines a resource-constrained environment (inspired by the PICO-8 philosophy but with 16-bit power), guaranteeing **perfectly identical and reproducible behavior on Raspberry Pi Zero W and PowKiddy RGB30**:
- **Same cartridge container**: dedicated profile flag in the `BMCART` header (`BM_FLAG_B16 = 2`).
- **Fixed resolution**: square **360×360** (or native 720×720 on RGB30).
- **Color palette**: 256 indexed colors (`SHEET8`).
- **Memory budget** (as built; the runtime is the same as a `.bm`, see `docs/B16.md`):
  - Lua heap: **64 MiB** (`LUA_MEM_LIMIT`, `src/script/luavm.c:13`). The 4 MiB of the first plan was never built.
  - Graphics: the `SHEET8` sheet of the cartridge. No graphics banks (D6).
  - Persistent save: **32 KiB** per slot (`SAVE_MAX`, `src/bm/runtime.c:3566`).
  - Maximum cartridge file size: no limit of its own. The Market takes 100 MiB a file.
  - No arbitrary token limit.
- **Audio**: 8 polyphonic voices.
- **CPU**: target 60 fps; no CPU budget and no automatic throttle promised (D4).
- **Controls**: SNES-style layout (d-pad + A, B, X, Y, L1, R1, Start, Select).
- **No sandbox** (D1): a `.b16` is a target. It has the same API as a `.bm`, including `ls`, `cart_*` and `math.random`.

## 3. Completion Criterion ("Done when")

The `.b16` profile is considered complete when:
1. *Yharnam* in `.b16` format runs perfectly indistinguishably on the Raspberry Pi Zero W and the PowKiddy RGB30 inside the sandbox.
2. The lint warnings (SDK + `mkbm.py`) are in place and the *Yharnam* `.b16` is verified.

Decisions D1-D6 taken on 2026-10-15 (`.b16` is a target, not a sandbox; no runtime profile; lint and checks are warnings only; no 60→30 fps promise; Lua heap 64 MiB and save 32 KiB unchanged; no graphics banks for Yharnam).

## Rules (do not break)

- Every cartridge writer keeps header bytes 120..127 and flag bit 4 (the compatibility block). `project.c` clears only bytes 104..119 (`bm_set_built_from`).
- An old file (bit 4 clear) reads as Pi only. An old `.b16` reads as Pi and RGB30.

- A `.b16` never overwrites the sources or the slot of the `.bm`.
- The `.b16` is a target, not a sandbox; the runtime is identical to the `.bm` one.
