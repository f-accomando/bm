When your program stops with a red message, do not panic. An error message is not an insult, it is the computer trying to help you. Read it slowly from the beginning. It usually tells you the name of the file, the number of the line and a short description of what went wrong.

The message "attempt to index a nil value" means that you tried to look inside something that does not exist. Maybe you wrote the name of a table incorrectly, or maybe you used it before you created it. Check the spelling of the name on that line, and make sure the table was filled before the game started to use it.

The message "attempt to perform arithmetic on a nil value" is a close cousin. You asked the computer to add, subtract or multiply, but one of the numbers was never given a value. Look for a variable that you forgot to set at the start, or one whose name has a small typing mistake in it.

The message "attempt to call a nil value" says that you tried to run a function that does not exist. Perhaps you misspelled its name, or perhaps you wrote the function below the place where you call it. The computer reads the file from top to bottom, so a function must be defined before the moment it is used.

The message "unexpected symbol near" tells you that the computer found something it did not understand, usually a missing comma, an extra bracket or a word in the wrong place. The mistake is often on the line before the one that is reported, so look at both.

The message "end expected" means that you opened a block, such as a function or a loop, but you never closed it. Every opening needs a matching ending. A good way to avoid this problem is to indent your code, so you can see at a glance which parts belong together.

The message "attempt to compare number with nil" appears when you ask whether a value is bigger than another value, but one of them is empty. This often happens with timers and scores that were never started at zero.

The message "bad argument number one, number expected, got string" says that a function wanted a number but you gave it a piece of text. Remember that the word "ten" and the number ten are very different things for a computer.

The message "stack overflow" usually means that a function keeps calling itself forever and never stops. Look for a place where you forgot to write the condition that ends the repetition.

The message "out of memory" means that the console has no more room. It often happens when a loop adds new objects to a table every frame and never removes the old ones. Delete things that are no longer needed, such as bullets that have left the screen.

Sometimes there is no message at all, and the game simply does something strange. In that case, print the value of your variables on the screen and watch them while you play. Most of the time you will see a number that is not what you expected, and that number will lead you to the problem.
